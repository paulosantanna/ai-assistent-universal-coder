# Cross-repository reconciliation

Updated: 2026-10-12
Source: IMG_2317–IMG_2321. Read when an interface points outside the current repository/category.

1. Resolve the callee using concrete contract identifiers, deployment/configuration evidence and the neighboring repository source. Name similarity is a candidate, not a resolved edge.
2. Keep owner/category/repository/subproject identities distinct. Metadata from a remote listing does not prove code content.
3. Investigate each candidate in a bounded work unit of the same canonical agent. Synthesis contains evidence pointers and unresolved gaps; raw credentials never enter it.
4. Compare both ends of the interface: route/method/topic, payload/version, authentication boundary, expected errors and sync/async semantics.
5. Merge only fields the new work unit actually investigated. Preserve richer existing keys/values and record contradictions explicitly.
6. Build the graph from verified dimension-8 interfaces. Never infer an absent edge from an architecture drawing or a shared technology label.
7. Compute fan-in from the complete resolved graph. Unknown destinations remain visible; do not silently remove them from totals.
8. Add vulnerability/EOL risk overlays with separate version provenance and a distinct unknown color. A topology edge and a risk verdict have different evidence.

Output: resolved edges, unresolved candidates, source pointers, changed fields and exact fleet coverage. Alphabetical or iteration order must not decide a tied candidate silently.

## New photograph protocol

Source: IMG_2735–IMG_2736. Discover related families in bounded batches (approximately 50, adjustable to actual limits), then checkpoint and map only consumed repositories in their owning sigla. Inspect all existing dimensions; the photo's eight-dimension shorthand does not delete the established vulnerability/EOL dimensions.
When the authorized organization is known, search its sigla prefix, then prove ownership/interface from source. If organization/access is unknown, ask for the actual org URL/access rather than invent it. A clone 404 may mean private/inaccessible, renamed or absent, not proof of deletion.
Keep DEPENDENCIAS-EXTERNAS-SIGLA.csv with caller, owner_sigla, consumed_repo, interface, source_pointer, status and gap. Keep REPOS-FALTANTES separately for failed repos inside the intake sigla. Retrofitting an existing map is additive: preserve investigated values, add unresolved edges/gaps and recompute coverage against the complete expected fleet; never call unknown evidence 100% mapped.
