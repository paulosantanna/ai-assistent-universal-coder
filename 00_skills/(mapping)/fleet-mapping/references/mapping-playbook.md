## Ordered execution

1. **BRIEFING/intake:** freeze repository universe, purpose, access mode, output home, freshness, coverage and stop conditions. Read parent/category/project intelligence in order, loading only relevant notes.
2. **RECON/preflight:** reuse valid maps; identify missing/stale repositories. Create a portable output package before writing delivered state. Keep source clones/worktrees distinct from the package.
3. **PLAN:** map verification to the ten dimensions; schedule dependency-safe bounded work units. Specify exact evidence/value checks, unresolved destinations and report acceptance.
4. **EXECUTE/micro:** map each repository, source versions and full code/interface paths; use current runtime evidence where authorized and read-only. Never claim a pod/image name proves a library version.
5. **EXECUTE/macro:** reconcile cross-repository interfaces; derive diagrams, fan-in, journeys, deployment and risk overlays only from the investigated micro maps.
6. **VERIFY:** check schema, claimed values at pointers, secret redaction, source freshness, complete intake coverage, graph consistency and output portability. Keep unknown distinct from absent/not-applicable.
7. **Report:** use report-design for generator/template/assets, complete tables, explanations, filters/export, accessible diagrams and real browser inspection. Rebuild twice; compare output hashes.
8. **DEBRIEF:** update the package continuity quartet, last verified coverage, gaps and exact next action. Promote only supported general lessons to parent scope without duplication.

## Package boundary

The output package contains entrypoint report, repository maps, data, evidence, scripts/assets needed for offline use and its task `.notebook/` quartet. The shared toolkit contains methodology, not a particular fleet's facts. Do not scatter generated fleet state into a shared utility tree.

## Gates and failure behavior

Missing source/access/schema or failed verification blocks the affected claim/delivery. Every declared percentage names its denominator. Report unexecuted checks as unverified. Do not weaken gates or overwrite real data to make a batch pass.
