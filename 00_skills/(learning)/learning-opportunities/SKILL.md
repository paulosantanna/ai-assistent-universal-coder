# learning-opportunities

Governance: CodENavi Full Workspace v2. Skill of `codenavi-agent`; inherit `AGENTS.md`.
Lifecycle: BRIEFING → RECON → PLAN → EXECUTE → VERIFY → DEBRIEF.

## Workflow

1. Run an After-Action Review: what should have happened; what happened; why they differ; what concrete behavior would change next time. Use inspected evidence and a blameless process view.
2. Filter each candidate by recurrence, systemic root cause, actionable change, prevention value/cost and non-obviousness. Most criteria must hold. One-off events and facts with no process change stay transient, never become a rule by default.
3. Route the result: lesson → LEARNING; validated decision/fact → MEMORY; resumption → PROGRESS/HANDOFF through chromatic-mega-brain and its quartet skills. Costly decision others must understand → create-adr. Stable repeated capability → skill-architect.
4. Apply the rule of three: first occurrence stays in the project; second in a different project is a suspected pattern; third supported occurrence may promote to category/root when that scope actually applies. Explicit urgent evidence-backed safety lessons may remain local without waiting for repetition.
5. Formulate each proposed lesson with trigger, root cause, testable prevention rule, destination/reuse scope and evidence pointers. “Be careful”, “communicate better” and “improve tests” are not actionable lessons.
6. Return recommendations and reasons for rejected noise; route writing to the owning continuity/ADR/skill procedure. Do not write the quartet or construct a new skill in this identification pass.

## Examples and errors

- Repeated output truncation across three projects → propose a root lesson: store bounded full results in an artifact and validate that artifact; cite all three occurrences.
- One pod failed with unknown cause → transient incident fact; investigate cause before promotion.
- Mapping the same type of repository requires repeating a stable procedure → candidate skill, handed to skill-architect.
- No recurrence proof → stay local; no root cause → incomplete candidate; vague rule → return to AAR. Never invent that this workspace has the photo's corporate history or number of lessons.

Input: completed work and inspected evidence. Output: reusable-versus-noise decisions, proposed statements, route, scope and promotion evidence.
