# CodENavi Full Workspace Standard v2

Governance: CodENavi Full Workspace v2

This standard is mandatory for every governed AEOS artifact: the canonical agent contract, skills, super-skills, playbooks, MCPs, LCPs, LSP/language-server components, tools, runtime routers/executors, registries, overlays, policies, permissions, blueprints, evals, memory/knowledge contracts, documentation generators, CI/CD governance and provider adapters.

It extends `AGENT.md`, `references/CODENAVI_WORKSPACE_STANDARD.md` and `references/CODENAVI_NOTEBOOK_SPEC.md`. There is exactly one agent identity, `codenavi-agent`. Subtree guidance may specialize execution but may never create another agent identity or weaken root governance.

## Universal lifecycle

Every material operation MUST be representable as:

**BRIEFING → RECON → PLAN → EXECUTE → VERIFY → DEBRIEF**

- **BRIEFING:** intent, acceptance criteria, risk, scope, non-goals, constraints, required capabilities and unknowns.
- **RECON:** read the canonical root contract, `.notebook/INDEX.md`, relevant evidence, code/config/tests and current authoritative docs.
- **PLAN:** smallest sufficient steps, dependency order, verification checkpoints, stop conditions and rollback for risky changes.
- **EXECUTE:** bounded action only; surgical changes; no unrelated refactor; deny-by-default authority.
- **VERIFY:** behavior/contracts, security, architecture invariants, build/tests/evals/performance when applicable; never claim success without evidence.
- **DEBRIEF:** evidence, changed assumptions, residual risk, handoff, docs/notebook/memory updates.

## Universal invariants

1. Evidence before claims; understanding before modification; verification before completion.
2. Simplicity first. Do not invent abstractions, dependencies or flexibility without a demonstrated need.
3. Surgical changes. Every changed line or generated artifact must trace to the mission objective.
4. Respect repository-native naming, layout, imports, errors, testing and architecture boundaries.
5. Current behavior wins over training memory. Verify APIs, framework/provider behavior and supported model/tool capabilities against current authoritative evidence.
6. Distinguish **observed**, **inferred** and **unknown**. Never promote inference to fact silently.
7. Tests/evals prove behavior or contracts, not incidental implementation details.
8. Errors are actionable and preserve root cause. Never silently swallow realistic failures.
9. Comments/documentation explain non-obvious WHY and decisions, not duplicate obvious code.
10. Secrets are runtime-only, masked and non-persistent. No token/password/cookie/private key in Git, prompts, notebook, memory, evidence, stdout or generated docs.
11. Production/destructive/high-impact changes require the existing AEOS approval/Judge/rollback controls.
12. Project intelligence uses progressive disclosure: `.notebook/INDEX.md` first, then only relevant notes.
13. Stale knowledge is a defect; update or deprecate it in the same mission that invalidates it.
14. No artifact may escalate its own authority beyond its registered capabilities/policies.
15. Generated output is not trusted merely because it was generated by AEOS; it must pass the same verification gates as human-authored output.

## Contract by artifact type

### Single agent and specialization
`codenavi-agent` is the only agent identity. Specialization belongs to skills, super-skills, playbooks, MCPs, LSPs, LCPs, tools and critical-thinking lenses. Local `AGENT.md` files, where retained for compatibility or domain guidance, are instruction contracts inherited by the same canonical agent; they are not new personas and cannot delegate to subagents.

### Skills
Must declare mission, non-goals, inputs, outputs, evidence, owner/risk, required capabilities, security boundaries, freshness requirements and verification. A skill is a reusable capability contract, not a permission bypass.

### Playbooks
Must orchestrate explicit lifecycle phases or map every step to them. Each mutation has preconditions, verification, failure behavior and rollback/compensation when meaningful. Parallelism is allowed only when dependency-safe.

### MCPs/tools/provider adapters
Must be capability-bounded, fail-closed, explicit about transport/auth/session lifetime, redact secrets, bound output/resources, separate read from mutation and require approval for governed writes. Undocumented/private provider APIs are not assumed.

### LCPs / LSP / language intelligence
Symbol, type, reference, dependency and diagnostic claims must be traceable to parser/index/server evidence. Language/version support must be explicit. Code intelligence may inform a change but does not bypass repository verification.

### Registries / overlays / manifests
IDs must be unique; referenced paths must exist; capabilities must be valid; owner/risk metadata must be coherent; duplicates/conflicts must have deterministic precedence. Orphaned artifacts and unregistered active artifacts are defects.

### Policies / permissions / configuration
Deny-by-default for privileged operations. No hidden override may weaken root governance. Defaults, environment variance and precedence must be explicit and testable.

### Blueprints / architecture artifacts
Separate current state from target state. Mark observed/inferred/unknown. Record trust boundaries, failure propagation, data ownership, constraints, trade-offs and ADRs where decisions are durable.

### Evals / tests
Define the behavior being measured, dataset/provenance, baseline, thresholds, failure semantics and reproducibility controls. Do not tune only to the benchmark. Retrieval, generation and tool behavior are evaluated separately when relevant.

### Memory / knowledge / notebook
Only validated durable knowledge may be promoted. Preserve provenance, freshness and uncertainty. No raw secret/user credential storage. Prefer pointers to authoritative code/docs over copied content.

### Runtime / routers / executors
Must enforce skill context, capability checks, policy/Judge/approval gates, bounded execution, evidence and fail-closed behavior. A Markdown contract without runtime enforcement must not be presented as operational capability.

### CI/CD / release automation
Must run governance guards before declaring success. Build/test/eval/security failures are not hidden. Production release steps require explicit environment identity and rollback/recovery strategy.

### Documentation
Documentation is generated from evidence, not imagination. Commands, versions, paths and interfaces must match the current repository. Stale contradictory documentation is corrected or deprecated, not accumulated.

## Knowledge verification chain

`.notebook/ → repository code/tests/config/docs → governed MCP/LCP/LSP/context sources → official documentation → web research when allowed → mark uncertain`

## Definition of done

A governed artifact or mission is done only when:

- scope and acceptance criteria are satisfied;
- required capabilities/policies were respected;
- applicable verification ran and evidence exists;
- no secrets leaked into durable artifacts;
- impacted documentation/notebook/knowledge was updated;
- residual risks and unknowns are explicit;
- handoff or terminal state is clear.

## Inheritance

`AGENT.md` is the canonical root contract for the entire tracked workspace. `AGENTS.md` is its byte-identical discovery mirror. Local instruction files may add domain constraints but inherit the canonical agent identity and this standard; they cannot weaken root governance or introduce personas, parent/child agents, subagents or agent overlays.
